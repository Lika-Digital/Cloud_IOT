# numpy: RANGE, not a hard pin, and deliberately so.
#
# The fleet spans Ubuntu 24.04 (Python 3.12) and 26.04 (Python 3.14). numpy 2.1.2
# predates Python 3.14 by a year, so it ships no cp314 wheel — on the 3.14 NUC
# `numpy==2.1.2` can only attempt a source build, which is why that venv had to be
# rebuilt by hand with relaxed pins and has since drifted (production is running
# 2.4.6 as of 2026-09-26). `upgrade.sh` only *warns* when pip fails, so the old
# hard pin silently failed on every upgrade while 2.4.6 stayed in place.
#
# A range makes the file match reality: pip sees the installed version already
# satisfies it and does nothing, instead of failing on every upgrade. Verified
# against the full backend suite on 2.1.2, 2.4.6 and 2.5.3 — 675 passed on each.
