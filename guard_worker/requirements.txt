# Guard worker venv — /opt/cloud-iot/guard/.venv
#
# Deliberately separate from backend/requirements.txt. openvino must never enter the
# backend venv: it is a large dependency on the process that serves the marina, and the
# whole point of the two-process split is that a detection-stack problem cannot take the
# dashboard down.
#
# Install with wheels only. A source build of numpy or openvino on the NUC takes tens of
# minutes and can fail halfway, leaving a venv that imports but does not work:
#
#   /opt/cloud-iot/guard/.venv/bin/pip install --only-binary=:all: \
#       -r /opt/cloud-iot/guard/guard_worker/requirements.txt
#
# Version pins are ranges, not exact. Ubuntu 26.04 ships Python 3.14 and an exact pin
# without a cp314 wheel falls back to a source build — the failure mode above. The NUC
# currently runs numpy 2.4.6; read the installed version rather than assuming it.

# The broker client. Needed by the worker entrypoint only — capture, recorder and watchdog
# stay stdlib-only so they keep working if anything here has a problem.
paho-mqtt>=2.1,<3

# Inference. openvino-telemetry IS installed by this line: pip pulls it in as a dependency
# of openvino (measured on cabinet 1, 2026-10-15: "Would install openvino-2026.4.1 openvino-telemetry-2025.2.0").
# This comment used to say it was not installed; that was a plan, never carried out.
# What keeps a marina pedestal from phoning home is the KERNEL FILTER in the unit
# (IPAddressDeny=any). install-guard.sh step 9 then removes the package only if a smoke test
# proves openvino loads and runs the model without it, and puts it back otherwise.
# OPENVINO_TELEMETRY_OPT_OUT=1 is a request the package honours by its own choice.
openvino>=2025.0

# Used by app/guard/pipeline.py for cropping, visibility measurement and tensor prep.
numpy>=2.1,<3
Pillow>=11
